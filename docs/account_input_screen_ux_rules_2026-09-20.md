# 입력/선택 필드 UI/UX 공통 가이드

`lib/features/account/additional_info_screen.dart`(회원가입/이력서 수정 화면)를 만들면서 확정한 규칙.
**이 화면에만 적용되는 게 아니라, 앞으로 다른 화면에서 텍스트필드/선택필드를 새로 만들 때도 그대로 따를 일반 원칙**으로 정리함.
코드가 바뀌면 이 문서도 같이 갱신할 것.

## A. 일반 원칙 (다른 화면에도 적용)

### A-1. 상태별 색상 규칙
- **평소(정상, 비포커스)**: 테두리 투명 또는 옅은 회색(`gray100`), 박스는 `gray50` 채움.
- **포커스**: `AppColors.navy`(남색). 커서 색(`cursorColor`)도 동일하게 남색.
  - 처음엔 브랜드 컬러인 `AppColors.carrot`(주황)을 썼는데, 에러 색(`urgent`, 빨강)과 채도/톤이 비슷해서 "포커스인지 에러인지 헷갈린다"는 피드백으로 남색으로 변경함(2026-09-20). **포커스 색과 에러 색은 반드시 확실히 다른 색 계열(예: 파랑 계열 vs 빨강 계열)로 분리할 것.**
- **에러**: `AppColors.urgent`(빨강). 테두리·커서·헬프 문구 색을 전부 이 색으로 통일.
- **경고 아닌 중립 안내(예: 진행 카운터)**: 에러 색과 구분되는 회색(`gray400`). 자세한 내용은 A-3 참고.
- 테두리 **두께는 상태와 무관하게 항상 동일**(예: 1.4)하게 하고 색상만 바꿀 것. 두께까지 다르면 시각적으로 필드마다 미묘하게 다르게 보여서 헷갈림 (실제로 `_GenderField`만 두께가 다르게 남아있던 버그가 있었음, 2026-09-20).

### A-2. 헬프/에러 문구 규칙
- `InputDecoration.helperText`를 쓰지 말고 **필드 박스 바로 아래에 별도 `Text` 위젯**으로 수동 렌더링할 것.
  - 이유: `InputDecoration.helperText`는 `OutlineInputBorder` 조합에서 입력 텍스트/라벨 시작 위치와 좌측 정렬이 미묘하게 안 맞는 문제가 있었음.
- **좌측 정렬 기준은 입력 텍스트가 아니라 필드 위 라벨(라벨의 좌측 패딩이 0이라면 문구도 좌측 패딩 0)과 맞출 것.** 이번에 입력 텍스트 시작점 기준으로 맞췄다가("실기기로 재보니 2.5dp 정도 안 맞음") 다시 "라벨과 시작점이 같아야 한다"는 피드백으로 정정한 적 있음 — 처음부터 라벨 기준으로 맞추면 이 과정을 생략할 수 있음.
- **문구가 뜨는 조건(경고 표시 여부)과 테두리가 빨간색이 되는 조건(`hasError`)은 반드시 하나의 변수로 묶어서 동시에 판단할 것.** 절대 따로 계산하지 말 것 — 따로 계산하면 "문구는 떠 있는데 테두리는 안 빨개짐"류의 불일치가 생김(실제로 겪은 버그, 2026-09-20).
  - 좋은 패턴: `build()` 안에서 `final xxxInvalid = ...;` 하나만 계산해서 `hasError: xxxInvalid`, `helperText: xxxInvalid ? 문구 : null`에 그대로 재사용.
- 위 동기화 덕분에, 별도 처리 없이도 "값이 유효하지 않은 동안은 포커스가 빠져도 테두리가 계속 빨간색으로 유지되고, 값을 고쳐야만 정상으로 복귀"하는 동작이 자연스럽게 성립함 (테두리 색 로직이 애초에 `hasError` 하나만 보고 포커스 여부와 무관하게 빨간색을 유지하기 때문).

### A-3. "입력 중" vs "필수인데 아직 다 안 채움" vs "다 채웠는데 형식이 틀림" 3단계 구분
자릿수가 정해진 필드(생년월일 8자리, 인증번호 등)에서는 상태를 3단계로 나눠서 다르게 표시할 것:
1. **아직 입력 중(자릿수 미달, 포커스 여부와 무관)**: 에러 아님. 회색으로 "n/N" 같은 중립적인 진행 카운터만 보여줌 (0자리일 땐 아예 안 보여줘도 됨). 테두리도 에러 색으로 바꾸지 않음.
2. **다 채웠는데 형식/값 자체가 틀림**: 빨간 에러 문구 + 빨간 테두리.
3. **Done(제출) 버튼을 눌렀는데 아직 다 못 채운 상태**: 그 순간부터는 "미완성도 에러"로 취급해서 빨간 에러 문구 + 빨간 테두리로 전환. 이후 사용자가 한 글자라도 더 입력하면(=`onChanged` 발생) 즉시 에러가 풀리고 다시 1번(회색 카운터) 상태로 돌아감.

이 3단계 구분은 생년월일 필드에 실제로 적용한 패턴이며(`birthHasError`/`birthHelperText`/`birthHelperColor`, `additional_info_screen.dart`), 자릿수 제한이 있는 다른 입력 필드(인증번호, 우편번호 등)를 만들 때도 동일하게 적용할 것.

**주의**: 진행 카운터(1번 상태)는 A-2의 "라벨 기준 좌측 정렬" 원칙의 예외임. 카운터는 "지금 입력 중인 숫자를 세고 있다"는 성격이라 **입력 텍스트가 시작하는 위치(좌측 12, contentPadding과 동일)**에 맞춰야 시각적으로 자연스러움. 반면 2·3번 상태(빨간 에러 문구)는 다른 필드 경고와 같은 성격이므로 그대로 라벨 기준(좌측 0)을 씀. 즉 **같은 필드 안에서도 상태(카운터 vs 에러)에 따라 정렬 기준이 달라질 수 있음** — `_TextField`의 `helperLeftPadding` 파라미터로 상태별로 다른 값을 넘겨서 구현함(기본값 0=라벨 기준, 카운터일 때만 12=입력 기준).

### A-4. 실시간 검증 시작 타이밍
필드에 값이 하나만 들어가도 바로 경고를 띄우면 너무 성급하고 산만하게 느껴짐. **검증을 시작하는 최소 글자수를 정해둘 것** (예: 전화번호는 "010"까지 채워질 수 있는 3자리부터 검사 시작 — 1자리("0")만 봐도 "010으로 시작 안 함"이라고 뜨는 건 과도함).

### A-5. 키보드 액션 체이닝
- 바로 아래에 다음 텍스트필드가 있으면 `TextInputAction.next` + `onEditingComplete`에서 `FocusScope.of(context).requestFocus(다음필드)`.
- 바로 아래가 선택형 필드(세그먼트 버튼, 바텀시트/화면 이동형 선택 등 텍스트 입력이 필요 없는 것)면 `TextInputAction.done` + `onEditingComplete`에서 `FocusScope.of(context).unfocus()`.

## B. 알려진 Flutter 버그 원인 & 재발 방지 패턴 (일반)

### B-1. 중첩 GestureDetector의 탭 가로채기 (gesture arena 충돌)
- 증상: 약관 "View" 링크, Done 버튼 등 특정 버튼이 탭해도 반응 없음.
- 원인: 넓은 영역을 덮는 `GestureDetector(onTap: 배경탭시 키보드 내림)`가 그 안의 개별 버튼/링크 `GestureDetector`를 감싸고 있으면, 제스처 아레나 충돌로 탭이 원하는 쪽에 전달되지 않을 수 있음.
- 해결 패턴: "배경 탭하면 키보드 내림" 제스처는 **꼭 필요한 범위(예: ListView)에만 좁게** 감싸고, 액션 버튼(Done 등)은 그 바깥의 형제(sibling)로 뺄 것. 체크박스+링크처럼 같은 행에 두 개의 탭 가능 영역이 있으면, 하나가 다른 하나를 감싸지 말고 같은 `Row`의 형제로 배치할 것.

### B-2. 포커스가 남은 채로 다른 화면으로 이동 → 복귀 시 엉뚱한 필드가 포커스됨
- 증상: 입력필드에 포커스(키보드)가 떠 있는 상태에서 다른 화면(선택 화면, 약관 상세 등)으로 이동했다가 돌아오면, 이동 전과 다른 필드에 갑자기 포커스가 잡히고 키보드가 다시 뜸.
- 원인: 이동 직전에 키보드를 안 내렸기 때문에 실제 필드의 `FocusNode`가 살아있는 채로 새 라우트가 뜨고, 복귀 후 리빌드되면서 플러터가 임의의 포커스 대상을 다시 지정함. 단순 `FocusScope.of(context).unfocus()`는 라우트 복귀 타이밍에 플러터 자체 포커스 복원 로직에 덮어써져서 안 먹힘.
- 해결 패턴: 화면을 이동시키는 함수의 **진입 시작 지점**에서, 보이지 않는 더미 `FocusNode`(`Focus(focusNode: dummy, child: SizedBox.shrink())`로 트리에 심어둠)로 포커스를 미리 옮겨서 키보드를 즉시 닫고, 이동 중에는 어떤 실제 입력필드도 포커스를 갖지 않게 만들 것. 복귀 직후에도 한 번 더 같은 처리를 해서 이중으로 방어.

### B-3. Lazy Sliver 목록에서 "선택된 항목으로 스크롤"이 안 먹힘
- 증상: 긴 선택 목록(국적, 비자 등)에서 이미 선택된 항목으로 자동 스크롤이 전혀 안 됨.
- 원인: `ListView(children: [...])`(builder 아님)도 내부적으로 `SliverList`의 lazy 레이아웃을 씀. 화면 밖 항목은 아직 RenderObject가 없어서 `Scrollable.ensureVisible(key.currentContext)`가 `currentContext`가 null이라 조용히 실패함.
- 해결 패턴: 2단계 스크롤. (1) 정렬된 리스트에서 선택 항목의 인덱스 × 예상 행 높이(+ 섹션 헤더 높이)로 대략적인 픽셀 오프셋을 계산해 `ScrollController.jumpTo()`로 먼저 이동. (2) 그다음 프레임에서 근처 항목들이 레이아웃 됐으므로 `Scrollable.ensureVisible()`로 정확히 보정.

### B-4. 정렬 요청 시 "알파벳순"의 의미 확인
- "알파벳순" 요청을 문자열 그대로 `compareTo`로 정렬하면, 코드에 숫자가 섞여 있을 때(`D-2`, `D-10` 등) `D-10`이 `D-2`보다 앞에 오는 식으로 어긋날 수 있음. 접두 문자는 알파벳순, 뒤 숫자는 숫자 크기순으로 비교하는 자연정렬(natural sort) 함수를 별도로 만들어서 처리할 것.

### B-5. 되돌릴 수 없는 동작(로그아웃, 탈퇴, 삭제 등)은 항상 확인 다이얼로그를 거칠 것
- 로그아웃/탈퇴 버튼을 눌렀을 때 확인 절차 없이 바로 실행되면, 오탭으로 인한 사고가 발생하기 쉬움.
- 패턴: `showDialog<bool>`로 `AlertDialog`를 띄우고, 취소(`false`)/실행(`true`) 두 버튼을 둠. 호출부에서 `if (confirmed == true) { 실제 동작 실행; }`.
- 위험도에 따라 실행 버튼 색을 다르게: 되돌릴 수 있는 동작(로그아웃)은 브랜드 색(`carrot`), 완전히 되돌릴 수 없는 동작(탈퇴/삭제)은 `urgent`(빨강)로 강조.
- 로그아웃처럼 "지금 어떤 계정 상태인지" 헷갈릴 수 있는 동작은, 다이얼로그 안에 현재 로그인 정보(SNS 제공자, 이메일 등)를 같이 보여줘서 사용자가 확인하고 실행하게 함.

## C. 이 화면(AdditionalInfoScreen)에 실제 적용한 예시

### C-1. 필드 구성 순서
1. 이메일 (SNS 계정 정보, 읽기전용 텍스트필드 스타일)
2. 이름 (Passport/ID)
3. 생년월일 (8자리)
4. 성별
5. 국적
6. 비자타입
7. 전화번호
8. 약관 동의 3종

에러 발생 시 포커스/스크롤 이동도 이 순서를 그대로 따름 (`_onComplete`의 `order` 배열).

### C-2. 필드별 검증 규칙

| 필드 | 필수 | 검증 규칙 | 헬프 문구 (색) | 키보드 |
|---|---|---|---|---|
| 이메일 | Y | 정규식 `^[^\s@]+@[^\s@]+\.[^\s@]+$` | `accountEmailInvalid` (빨강, 형식 오류 시) | `emailAddress` |
| 이름 | Y | 한글만(`^[가-힣\s]+$`) 또는 영문만(`^[A-Za-z\s'\-.]+$`), 혼용/숫자/특수문자 불가 | `accountNameMixedScript` (빨강) | 기본 |
| 생년월일 | Y | 8자리 숫자 + 실제 유효한 날짜 (`_isValidBirthDate`: 연도 1900~올해, 월 1~12, 일은 해당 월 실제 일수 이내) | 1~7자리: "n/8"(회색) / 8자리인데 무효 or Done 눌렀는데 미완성·무효: `accountBirthDateInvalid`(빨강) | `number`, `digitsOnly` + 8자리 제한 |
| 성별 | Y | 남/여 단일 선택 | 없음 | - |
| 국적 | Y | `NationalitySelectScreen`에서 선택, 국기 이모지 같이 표시 | - | - |
| 비자타입 | Y | `showVisaTypeSheet` 바텀시트에서 선택 | - | - |
| 전화번호 | Y | 3자리 이상 입력됐는데 `010`으로 시작 안 하면 무효 | `accountPhoneMustStart010` (빨강) | `phone` |
| 약관 동의 | Y | 3개 전체 체크 | - | - |

- 이름 필드의 숫자/특수문자는 한글 전용/영문 전용 정규식 둘 다에 안 걸리므로 자동으로 "혼용"으로 취급되어 막힘 — 별도 숫자 금지 로직 불필요.
- 생년월일의 3단계 상태 전환(A-3 참고)은 `build()`의 `birthLen`/`birthHasError`/`birthHelperText`/`birthHelperColor` 계산부와 `_TextField(helperColor: ...)` 파라미터로 구현함.

### C-3. 국적 선택 (`NationalitySelectScreen`)
- 데이터 소스: `world_countries.dart` (mledoze/countries 기준 250개 전체) — DB `countries` 테이블은 20개뿐이라 국적 선택용으로는 부족해서 별도 하드코딩.
- "Major countries" 섹션: 기존 20개 국가(앱이 16개 언어로 이미 번역해둔 국가, `app_strings.countryName()` 커버 범위)를 우선 노출.
- 선택된 국가로 B-3 패턴으로 자동 스크롤 이동.
- 선택 완료 후 `_SelectField`에 국기 이모지(`flagEmoji(code)`) + 국가명이 같이 표시됨.

### C-4. 비자타입 선택 (`showVisaTypeSheet`)
- 전체화면이 아니라 바텀시트로 표시 (전체화면이었을 때 시각적으로 부실하다는 피드백).
- "자주 찾는 비자" 구분 없이 전체 비자를 B-4의 자연정렬로 단일 목록 표시.
- 선택된 비자로 B-3 패턴으로 자동 스크롤 이동.

### C-5. 브랜드 아이콘 (SNS 로그인/이메일 표시용)
- 구글: `assets/brand/google_g.svg` — 공식 4색 G 로고 그대로 사용 (색 강제 안 함).
- 애플: `assets/brand/apple.svg` — Simple Icons 실루엣, `colorFilter`로 검정/흰색 강제.
- 페이스북: `assets/brand/facebook_f.svg` — **원 없는 순수 "f" 글자 형태**여야 함. Simple Icons의 "원형 뱃지"(원+f 컷아웃이 하나의 도형) 버전은 파란 버튼 위에서 흰 원판처럼 이상하게 보여서, Font Awesome Free의 `facebook-f` 글리프(원 없는 순수 f, viewBox `0 0 320 512`, CC BY 4.0)로 교체함. 구글(G만)·애플(실루엣만)처럼 심볼만 있는 스타일과 통일하기 위함.
- 이메일 필드 안의 작은 SNS 아이콘(`_snsProviderIcon`)은 구글/애플은 그대로, 페이스북만 별도로 `Container(파란 원 배경) + 흰색 f`로 직접 합성 — 로그인 버튼(`login_signup_sheet.dart`)에서는 버튼 배경 자체가 파란 사각형이라 f만 흰색으로 렌더링.

### C-6. 마이페이지 로그아웃/탈퇴 확인 다이얼로그 (`my_page_screen.dart`)
- B-5 패턴을 그대로 적용. 로그아웃 다이얼로그는 제목에 SNS 제공자명(`_providerLabel`)+이메일을 보여주고, 실행 버튼은 `carrot`. 탈퇴 다이얼로그는 "모든 정보가 삭제되며 복구할 수 없습니다" 경고 + 실행 버튼은 `urgent`(빨강).
- 원래는 버튼 누르면 확인 없이 바로 `logout()`/`withdraw()`가 실행됐음 — 이번에 확인 다이얼로그를 추가함(2026-09-20).

### C-7. 설정 화면 계정 섹션 라벨 중복 (`settings_screen.dart`)
- 계정 섹션의 회색 소제목(`_SectionHeader`)과 그 아래 탭 가능한 행이 로그인 상태일 때 둘 다 "My Page"로 똑같이 표시되는 중복이 있었음.
- 다른 섹션들(알림/언어 등)은 전부 위에 소제목이 있어서 이 섹션만 없애면 구조가 비대칭이 되므로, 소제목 자체를 없애기보다 **"Account"(계정)로 교체**해서 중복 해소 + 패턴 유지 둘 다 만족시킴 (`settingsAccountSection` 문자열, 2026-09-20).

## D. 아직 미결정/유의 사항

- 비자 발급일/만료일 필드는 이번 범위에서 제외 (추후 검토, `docs/apply_signup_scenario_2026-09-19.md` 참고).
- SNS 소셜 로그인은 아직 실제 OAuth 연동 전 — provider/email 모두 stub 값.
- 이 화면의 모든 상태(`ApplicantProfile`)는 아직 `account_provider.dart`에 메모리로만 저장 — 앱 재시작하면 초기화됨, Supabase 연동 전.
